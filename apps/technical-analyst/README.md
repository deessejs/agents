# `apps/technical-analyst`

The first eve agent: an automated engineering digest of GitHub activity for
`env.GITHUB_ORG / env.GITHUB_REPO`, sent by email on a daily and weekly cadence.

Built on the shared workspace packages:

- `@workspace/env` — Zod-validated env at boot (`.passthrough()` so deployment
  variables like `VERCEL_*` and `NODE_ENV` are ignored).
- `@workspace/github` — Octokit + throttling + REST projections.
- `@workspace/email` — Resend wrapper + React Email templates + content-derived
  idempotency key.

## Architecture (Eve-native)

```
apps/technical-analyst/
├── agent.ts                  # defineAgent({ model: minimax(env.LLM_MODEL_ID), defaultTools: false })
├── instructions.md           # Role, scope, editorial rules, refusal patterns
├── env.ts                    # Zod composition of @workspace/env + agent keys
├── lib/
│   ├── state.ts              # eve defineState handles (edition, sourceCorpus, deliveryLog)
│   └── kv-edition.ts         # Vercel KV: writePending / readEdition / markDelivered
├── tools/
│   ├── collect_activity.ts   # GitHub → source corpus; pause-before-collect
│   ├── submit_digest.ts      # Validate, render, deliver (idempotent retry via KV)
│   └── no_reply.ts           # Opt-in no_reply for quiet weeks
└── schedules/
    ├── daily-digest.ts       # 0 20 * * * — daily digest
    └── weekly-recap.ts       # 0 16 * * 5 — weekly recap
```

`defaultTools: false` disables eve's filesystem / shell / network defaults —
the agent advertises only its two business tools. Vercel Cron entries are
auto-generated by `eve build` from each schedule's `cron` field; no
`vercel.json` cron block is needed.

## Tool contract

### `collect_activity({ kind: "daily" | "weekly" })`

- Throws immediately if `process.env.AGENTS_PAUSED === "true"` (pause-before-
  collect).
- Computes a **canonical UTC window**:
  - **daily** : previous calendar day in UTC
    (`[startOfDay(UTC) − 1d, startOfDay(UTC)]`).
  - **weekly** : previous ISO week
    (`[last Monday 00:00 UTC, this Monday 00:00 UTC]`).
- Fetches 9 GitHub endpoints (merged PRs, open PRs, opened + closed issues,
  Dependabot alerts, CodeQL alerts, secret-scanning alerts, failed workflow
  runs, releases) in parallel via `@workspace/github`. Pagination is bounded
  with an explicit cap; we don't chase links forever.
- Projects each entry to a corpus record `(id, kind, url, title, meta)`. IDs
  are **repo-qualified** (`deessejs/agents:pr:142`) so multi-repo expansion is
  trivial later.
- Secret-scanning alerts are reduced to `(number, secret_type, state)` — the
  secret value itself never reaches the model.
- Essential sources (Dependabot, CodeQL, secret-scanning) fail loud; optional
  sources (issues, runs) report per-source availability.
- Persists `edition`, `sourceCorpus`, `weeklyMetrics` into session.

### `submit_digest({ kind, report, preview? })`

- Re-checks `AGENTS_PAUSED` defensively.
- Reads `edition` + `sourceCorpus` from session; refuses to render if the
  edition hasn't been collected.
- If the KV record for this edition is already `delivered`, returns
  `{ status: "already-delivered", messageId }` and exits — Resend is not
  called twice.
- Validates `report` against a strict Zod schema (4 daily sections / 7 weekly
  sections; each item is `{ text, referenceId }`). Unknown top-level keys
  are rejected via `.strict()` (re-validated explicitly because provider
  adapters sometimes drop them).
- Resolves every `referenceId` against the corpus. Rejects the call if any id
  is unknown or if a section cites a source kind that isn't in its allowlist.
- Renders with React Email (`renderDigest` from `@workspace/email`). URLs and
  titles come from the corpus, not the model.
- `preview: true` writes the rendered HTML to `tmp/preview-…html` and skips
  both send and KV record.
- Delivery: `createEmailClient.send(...)` (Resend, RFC 8058 headers,
  content-derived idempotency key) → writes the delivery record to KV with
  `markDelivered`.
- Pre-writes the KV record with `status: "pending"` BEFORE sending so a retry
  reuses the persisted payload + key — Resend deduplicates within its 24h
  retention window.
- `endsTurn: true` — the model has nothing more to say once the email is
  delivered (or the preview is on disk).

## Schedules

| File                              | Cron (UTC)            | Coverage              |
| --------------------------------- | --------------------- | --------------------- |
| `agent/schedules/daily-digest.ts` | `0 20 * * *`          | previous calendar day |
| `agent/schedules/weekly-recap.ts` | `0 16 * * 5`          | previous ISO week     |

Both schedules fire-and-forget a markdown prompt into the agent. The model
is expected to call `collect_activity` then `submit_digest`; for quiet weeks,
the weekly prompt has the `no_reply` opt-in.

## Delivery identity + retry

- `editionId = base64url(org | repo | kind | periodStart | periodEnd | recipient).slice(0,24)` — the canonical identifier of the edition.
- The Resend idempotency key is
  `digest:send:<sha256(subject|html|text|to).slice(0,16)>` — derived from
  content, not from the model. Retries with the same payload reuse the same
  key.
- Cross-session persistence in Vercel KV (key `agent:<slug>:edition:<editionId>`)
  holds the rendered HTML, text, subject, idempotency key, and Resend
  `messageId`. Status transitions: `pending` → `delivered`.
- A throw from `submit_digest` leaves the record in `pending` (or absent);
  the schedule's run-finished event shows an unsuccessful run, and the next
  attempt with the same inputs is a no-op on Resend.

## Quality gates

- `pnpm --filter agent-technical-analyst exec tsc -p . --noEmit` — typecheck
- `pnpm --filter agent-technical-analyst test` — vitest (acceptance)
- `pnpm oxlint apps/technical-analyst` + `pnpm oxfmt apps/technical-analyst`

`eve dev` / `eve build` are the deployment gate and require Node.js ≥ 24;
CI / production must run on Node 24 to confirm discovery + build.

## Acceptance criteria

The 11 tests in `tests/acceptance.test.ts` cover the PR refactor brief's
acceptance criteria:

| #   | Criterion                                           | Coverage                              |
| --- | --------------------------------------------------- | ------------------------------------- |
| 1   | Eve discovers tools/schedules via filesystem shape   | `agent.ts` + `instructions.md` + tools directory present, `defineAgent`/`defineTool` strings |
| 2   | Strict Zod rejects unknown top-level keys           | `submit_digest` re-validates with `.strict()` |
| 3   | `collect_activity` computes counts + corpus         | corpus + counts assertion             |
| 4   | Repo-qualified ids in the corpus                    | `deessejs/agents:pr:…` ids            |
| 5   | Synthetic secrets excluded from model data            | `secret-scanning-alerts-synthetic.json` is not in corpus |
| 7   | Fabricated references rejected by `submit_digest`     | unknown id + kind/citation mismatch   |
| 8   | Render uses authoritative URLs from the corpus      | rendered HTML grep for fixture URL    |
| 9   | `preview: true` skips delivery-state mutation      | preview branch returns `{ status: "preview" }` |
| 10  | Pause kills the run defensively                     | `AGENTS_PAUSED=true` throws at submit |

Criteria 1–3 (Eve discovery / build / schedule dispatch) require running the
eve CLI; CI exercises them on Node 24 via `eve info` + `eve build`.

## What this agent does NOT do (v1)

- No multi-recipient digests (deferred to v2).
- No inbound email channel — the digest is one-way.
- No auto-fixing of issues / PRs / alerts.
- No non-GitHub data sources (Linear, PagerDuty, Datadog, Sentry).
- No Resend webhook receiver (v2).
- No auto-suppression on bounce (v2).
